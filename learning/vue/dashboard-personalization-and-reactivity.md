## 작업 시작 메모

- 원격 변경사항을 로컬 작업본으로 받은 뒤 프로젝트를 열어 확인한다.
- 백엔드 작업본과 프런트 대시보드 작업본은 역할에 맞는 IDE로 각각 연다. 사용한 제품명, 프로젝트명, 경로 및 설정값은 원본에만 둔다.
- 프런트에서 화면을 만들 때는 Vue와 JavaScript 문법을 직접 확인하고, 공통 참조를 위해 `inject` 사용 방식도 함께 살펴본다.
- 서버와의 DB 통신은 백엔드가 담당하고, 프런트에서는 공통 API 호출 모듈과 `fetch` 계열 호출 흐름을 확인한다.

## 사용자별 대시보드

- 대시보드는 사용자별 커스터마이즈가 가능하다.
- 기본 페이지는 삭제하지 못하게 두고, 추가 페이지는 자유롭게 만들며 이름도 변경할 수 있다.
- 위젯 정렬은 기본 순서를 사용하되, 사용자 옵션과 위젯 설정에서 역순으로 바꿀 수 있다.
- 팝업 단위로 제어할 수 있고, 변경 내용은 한 번에 저장한다. 다음 로그인 때 마지막으로 적용한 화면 구성이 보이는지 확인한다.

## 기본 위젯과 표시 범위

- 기본 대시보드에는 원청용과 하청용 위젯 구성이 있다.
- 위젯은 현장 귀속에 따라 데이터가 바뀌는 유형과, 공지사항처럼 같은 데이터를 보여주는 유형으로 나뉜다.
- 표시 범위는 공용, 기업 전용, 협력사 전용으로 구분한다. 화면의 색상과 아이콘으로 범위와 현장 귀속 여부를 구별한다.
- 공용과 기업 전용 위젯은 진한 색, 협력사 전용 위젯은 연한 색으로 표시하는 기존 기준을 확인한다.

## 3D 위젯과 확인할 점

- CCTV처럼 3D 배치가 필요한 항목은 위젯 안에서 배치되도록 구성한다.
- 3D 화면이 바뀔 때는 로딩 상태를 보여 준다. 준비 완료 여부를 반환하는 불리언 값과 그 값을 사용하는 로직을 확인한다.
- 기존 화면의 기능을 Vue 위젯으로 옮겨 가시화하고, 위젯 내부 데이터를 채우는 작업이 남아 있다.

- 사용자 옵션 변경이 위젯 정렬과 표시 순서에 반영되는가?
