# 서브쿼리 별칭과 존재 조건 점검

- 작성일: 2026-09-15
- 분류: SQL 학습
- 상태: 일반화 완료

## 목적

복잡한 조회문에서는 각 쿼리 범위의 역할을 구분하고, 조건에 맞는 관련 행의 존재 여부를 명확히 표현해야 한다. 별칭과 `EXISTS` 또는 `IN` 조건을 일관되게 사용하면 검토와 수정이 쉬워진다.

## 별칭 사용 원칙

- 각 `FROM` 항목에는 짧고 의미가 드러나는 별칭을 부여한다.
- 바깥 쿼리와 서브쿼리에서 같은 별칭을 재사용하지 않는다.
- 열 참조에는 필요한 범위에서 별칭을 붙여 어느 테이블의 값인지 분명히 한다.
- 상관 서브쿼리는 바깥 행과 연결하는 조건을 눈에 띄게 배치한다.

## `EXISTS`와 `IN`의 선택

`EXISTS`는 관련 행이 하나라도 있는지를 확인할 때 적합하다. 서브쿼리의 선택 목록은 결과값 자체가 아니라 존재 여부만 필요하므로 간단한 상수를 사용할 수 있다. 이때 서브쿼리 안에서 바깥 쿼리의 키와 연결하는 조건을 명시한다.

`IN`은 바깥 열의 값이 서브쿼리가 반환한 값 목록에 포함되는지 확인할 때 사용한다. 비교하는 열의 개수와 순서, 자료형이 서브쿼리 선택 목록과 맞아야 한다. 여러 열을 비교해야 하면 지원하는 DBMS 문법과 `NULL` 처리 방식을 먼저 확인한다.

두 표현은 일부 조건에서 같은 결과를 낼 수 있지만, `NULL`, 중복, 실행 계획에 따른 차이가 있을 수 있다. 관례만으로 기계적으로 바꾸지 말고 의도와 실제 데이터를 기준으로 선택한다.

## 검증 체크리스트

- 바깥 쿼리와 서브쿼리의 연결 키가 업무 관계를 정확히 표현하는지 확인한다.
- 별칭 오타나 범위를 벗어난 열 참조가 없는지 확인한다.
- `IN`의 반환 열 수와 비교 열 수가 일치하는지 확인한다.
- `NULL`이 조건 결과에 미치는 영향을 테스트 데이터로 확인한다.
- 변경 전후 결과 건수와 대표 사례를 비교하고, 실행 계획은 승인된 비운영 환경에서만 확인한다.
