# Git 브랜치 병합과 체리픽 판단 기준

## 병합을 선택하는 경우

작업 브랜치의 변경사항 전체를 통합 브랜치에 반영해야 하면 병합을 사용한다.

1. 반영받을 통합 브랜치로 이동한다.
2. 원격 변경사항을 가져와 기준 브랜치 상태를 최신으로 맞춘다.
3. 작업 브랜치를 병합한다.
4. 충돌이 발생하면 파일 단위로 의도를 확인하고 해결한다.
5. 빌드·핵심 기능 검증 후 원격 저장소에 푸시한다.
6. 병합 커밋과 변경 파일을 원격 저장소에서 다시 확인한다.

## 체리픽을 선택하는 경우

작업 브랜치의 모든 변경이 아니라 특정 커밋 또는 파일 변경만 다른 브랜치에 반영해야 하면 체리픽을 사용한다.

1. 대상 브랜치로 이동한다.
2. 반영할 커밋을 오래된 순서부터 선택한다.
3. 한 커밋씩 체리픽하고, 매 단계에서 충돌을 해결한다.
4. 필요한 커밋만 모두 반영됐는지 변경 파일 목록과 기능으로 확인한다.
5. 검증 후 푸시한다.

## 확인 항목

- 대상 브랜치와 원본 브랜치를 반대로 선택하지 않았는지
- 작업 트리에 커밋하지 않은 변경이 없는지
- 병합 또는 체리픽 전에 최신 원격 변경을 반영했는지
- 충돌 해결 후 테스트와 변경 파일 검토를 했는지
- 통합 브랜치에 직접 반영할 권한·검토 절차가 있는지

## 주의사항

- 통합 브랜치에 영향이 큰 변경은 PR 검토와 승인 절차를 거친다.
- 실제 저장소 URL, 프로젝트별 브랜치명, 배포 서버·CI/CD 주소는 이 문서에 기록하지 않는다.
- 체리픽을 반복 적용할 때는 이미 반영된 커밋인지 먼저 확인해 중복 적용을 피한다.
