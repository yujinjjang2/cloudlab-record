# 기능 브랜치 작업 완료 체크리스트

## 개발 완료 전

- 기능 요구사항과 변경 범위를 확인한다.
- 변경 파일에 테스트용 코드, 환경별 설정, 인증 정보가 남아 있지 않은지 확인한다.
- 로컬에서 주요 기능과 오류 경로를 검증한다.

## 커밋과 푸시

1. 변경 파일을 검토한다.
2. 하나의 목적을 설명하는 커밋 메시지로 커밋한다.
3. 작업 브랜치에 푸시한다.
4. 원격 저장소에서 커밋과 변경 파일이 정상 반영됐는지 확인한다.

## 통합 요청

- 통합 대상 브랜치가 맞는지 확인한다.
- 변경 목적, 검증 결과, 영향 범위를 PR 설명에 기록한다.
- 리뷰·승인 절차 후 병합한다.
- 배포 전후에 팀의 변경·공지 절차를 따른다.

## 장애 예방

- 다른 작업자의 변경과 겹치는 파일은 미리 공유한다.
- 병합 충돌은 자동 선택하지 말고 양쪽 변경 의도를 비교한다.
- 배포 환경의 URL, 계정, 서버 정보는 코드·커밋·기록 문서에 포함하지 않는다.
