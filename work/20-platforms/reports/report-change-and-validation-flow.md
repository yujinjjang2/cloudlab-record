# 리포트 변경과 검증 흐름

- 작성일: 2026-09-11
- 분류: 플랫폼 / 리포트
- 상태: 일반화 완료

## 목적

리포트 수정은 원본을 보존한 상태에서 별도의 작업본으로 변경하고, 데이터와 화면을 각각 검증한 뒤 정해진 변경 관리 절차를 통해 반영한다.

## 작업 흐름

1. 변경 전 리포트와 관련 설정의 보존 상태를 확인한다.
2. 원본과 분리된 작업본에서 수정 범위와 영향을 받을 출력 항목을 정한다.
3. 데이터 변경은 입력값·데이터 집합·표현식의 이름과 연결 관계를 함께 점검한다.
4. 화면 변경은 표시 조건, 열 존재 여부, 문구 및 서식이 의도대로 동작하는지 확인한다.
5. 미리보기 또는 안전한 검증 환경에서 대표 조건과 경계 조건을 실행한다.
6. 변경 관리 절차에 따라 검토 가능한 단위로 반영하고, 반영 후 동일한 검증을 다시 수행한다.

## 검증 체크리스트

- 입력값과 데이터 집합의 이름·형식·필수 여부가 일치하는가
- 데이터가 없거나 선택 조건이 달라져도 화면이 깨지지 않는가
- 조건부 표시 항목이 참·거짓 양쪽 조건에서 올바르게 보이는가
- 미리보기 결과가 변경 의도와 일치하고 기존 출력 항목이 유지되는가
- 다른 사용자가 확인할 수 있는 검증 환경에서 변경 범위와 결과를 재현할 수 있는가

## 기록 원칙

이 문서에는 일반화한 절차와 검증 기준만 기록한다. 실제 리포트 파일, 소스·쿼리 전문, 데이터 값, 저장소·배포 환경 식별자, 접속 정보는 반입하지 않는다.
