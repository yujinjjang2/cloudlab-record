# 모바일 API 변경과 검증 흐름

- 작성일: 2026-09-14
- 분류: 플랫폼 / 모바일
- 상태: 일반화 완료

## 목적

모바일 화면과 연결된 API를 변경할 때는 변경 범위를 추적 가능한 단위로 분리하고, 자동화된 단위 테스트와 요청 기반 검증을 함께 수행해 회귀를 줄인다.

## 작업 흐름

1. 변경 요청의 목적, 영향 화면, 입력·출력 계약을 확인하고 별도 작업 브랜치를 만든다.
2. 관련 API의 요청 처리, 업무 로직, 데이터 접근, 응답 모델을 따라가며 수정 범위를 정한다.
3. 데이터 조회 또는 변환 로직과 응답 모델을 함께 수정해 필드명·형식·필수 여부가 일치하도록 한다.
4. 로컬 검증 환경에서 대표 입력값으로 요청을 보내고, 응답 형식과 오류 처리를 확인한다.
5. 단위 또는 통합 테스트를 추가·보완해 정상, 빈 결과, 잘못된 입력 같은 핵심 경우를 자동으로 확인한다.
6. 검토 가능한 단위로 병합한 뒤, 변경 관리 절차에 따른 안전한 검증 환경에서 재확인한다.

## 검증 체크리스트

- 요청 파라미터의 이름·형식·필수 여부가 API 계약과 일치하는가
- 응답 모델이 필요한 값을 빠짐없이 전달하고 빈 결과도 안정적으로 처리하는가
- 데이터 접근 결과가 화면에서 기대하는 정렬·형식·기본값과 맞는가
- 자동화 테스트가 정상 흐름과 오류·경계 조건을 모두 다루는가
- 병합 후에도 마지막 변경분이 포함되어 있고, 검증 환경에서 동일한 결과가 재현되는가

## 기록 원칙

이 문서에는 일반화한 절차와 검증 기준만 기록한다. 실제 저장소·브랜치·배포 환경 식별자, 접속 주소, 인증 정보, API 경로, 소스·쿼리 전문, 로그와 운영 데이터는 반입하지 않는다.
