# 메뉴 권한 요청의 일괄 적용과 검증

- 작성일: 2026-09-18
- 분류: 유지보수 · 접근 관리
- 상태: 일반화 완료

## 목적

여러 조직 또는 사용자 집단에 기능 메뉴를 열어 달라는 요청은 대상 범위와 권한 수준을 분리해 확인해야 한다. 요청 내용을 그대로 등록하면 읽기 전용 사용자에게 변경 권한을 주거나, 일부 대상만 빠지는 문제가 생길 수 있다.

## 적용 전 범위 확인

1. 요청 대상이 한 조직인지, 상위 조직과 연결된 여러 하위 조직인지 확인한다. 상위 조직에 메뉴를 열었다고 연결 조직에 자동으로 같은 메뉴가 열리는지 추정하지 않는다.
2. 요청이 메뉴 표시 문제인지, 실제 기능 접근 문제인지 구분한다. 메뉴가 보이지 않는 경우에는 조직별 메뉴, 그룹별 메뉴, 사용자별 예외 중 어느 단계에서 빠졌는지 확인한다.
3. 메뉴별로 필요한 동작을 구분한다. 조회, 등록·수정, 기준 정보 관리, 종료된 대상의 조회는 같은 권한으로 취급하지 않는다.
4. 각 사용자 집단에 부여할 메뉴 목록을 표로 정리한다. 메뉴를 추가하는 역할과 조회만 하는 역할을 한 칸에 합치지 않으며, 개별 예외도 따로 표시한다.
5. 비슷한 과거 적용 사례는 메뉴 구성만 참고하고, 과거 대상이나 권한을 그대로 복제하지 않는다. 이전 사례의 대상 범위, 연결 관계, 메뉴 버전이 현재 요청과 같은지 먼저 확인한다.

## 권한 매트릭스 작성

요청을 받은 뒤 바로 메뉴를 등록하지 말고, 아래처럼 역할별 기대 동작을 먼저 정리한다. 역할명과 기능명은 설명용 예시다.

| 기능 구분 | 관리 역할 | 일반 작업 역할 | 외부 협업 역할 | 조회 역할 |
| --- | --- | --- | --- | --- |
| 분류·기준 정보 관리 | 허용 | 제외 | 제외 | 제외 |
| 문서 또는 업무 항목 등록 | 허용 | 허용 | 필요한 범위만 허용 | 제외 |
| 현재 대상 조회 | 허용 | 허용 | 허용 | 허용 |
| 종료된 대상 조회 | 허용 | 필요한 범위만 허용 | 필요한 범위만 허용 | 허용 |
| 통계·관리 화면 | 허용 | 제외 | 제외 | 제외 |

이 표는 실제 메뉴 목록을 대체하지 않는다. 각 칸을 실제 메뉴 단위로 풀어 쓴 뒤, 요청자가 기대한 역할별 차이가 맞는지 확인한다. 예를 들어 외부 협업 역할에 등록 기능을 주더라도, 전체 분류나 관리 기능까지 함께 열리는지 별도로 검사해야 한다.

## 등록 순서

기본 메뉴 구성을 먼저 조직 단위에 연결한 뒤, 공통 권한은 그룹 단위로 적용한다. 특정 사용자만 다른 권한이 필요할 때만 개별 사용자 설정을 추가한다. 순서를 뒤집으면 그룹 또는 사용자 화면에서 선택할 수 있는 메뉴 후보가 없거나, 일부 메뉴만 보이는 상태가 생길 수 있다.

1. 기능과 메뉴 정의가 이미 등록되어 있는지 확인한다. 새 기능이면 메뉴 구조와 연결 대상이 먼저 준비되어야 한다.
2. 조직별 기본 메뉴에 요청 기능을 등록한다. 이 단계에서는 대상 조직이 사용할 수 있는 메뉴 후보를 만든다.
3. 역할별 그룹 메뉴에 매트릭스에 맞는 메뉴를 배정한다. 그룹별로 조회·등록·관리 메뉴를 구분해 선택한다.
4. 여러 연결 조직이 같은 구성을 써야 할 때만 일괄 적용 작업을 만든다. 적용 대상 목록과 메뉴 목록을 각각 등록하고, 실행 전 두 목록을 다시 확인한다.
5. 특정 사용자의 예외는 마지막에 추가한다. 그룹 권한을 대체하는지, 그룹 권한에 메뉴를 추가하는지 기록한다.

일괄 적용은 같은 메뉴 구성이 필요한 대상에만 쓴다. 대상마다 허용 기능이 다르면 일괄 적용 후 개별 삭제로 맞추지 말고, 처음부터 대상을 나누거나 역할별 그룹 설정으로 처리한다. 적용 사유에는 고객명이나 사용자 이름 대신 요청 유형과 적용 범위만 기록한다.

## 일괄 적용 전후 확인

일괄 작업을 실행하기 전에는 아래 네 가지를 교차 확인한다.

1. 대상 목록: 상위 조직, 연결 조직, 제외 조직이 요청서와 일치하는가?
2. 메뉴 목록: 조회 전용 메뉴와 등록·관리 메뉴가 섞여 있지 않은가?
3. 적용 단위: 조직별 기본 메뉴만 추가하는지, 역할별 그룹 메뉴까지 바꾸는지 분명한가?
4. 되돌림 기준: 잘못 적용됐을 때 삭제할 대상과 메뉴 조합을 별도로 식별할 수 있는가?

적용 직후에는 대상 수와 실제 적용 결과 수를 비교한다. 차이가 있으면 재실행하지 말고, 이미 적용된 대상과 누락 대상을 나눠 원인을 확인한다. 중복 실행은 같은 메뉴가 여러 번 보이거나, 원래 있던 예외 권한을 덮는 문제를 만들 수 있다.

## 검증

검증은 설정 화면만 보는 것으로 끝내지 않는다. 조직별, 그룹별, 사용자별 화면과 실제 사용자 화면을 함께 확인한다.

| 확인 단계 | 확인 내용 | 실패 시 우선 점검할 위치 |
| --- | --- | --- |
| 조직 단위 | 대상 조직에 기본 메뉴 후보가 생겼는가? | 조직별 메뉴 등록과 일괄 적용 대상 |
| 그룹 단위 | 역할마다 매트릭스와 같은 메뉴가 보이는가? | 그룹별 메뉴 등록과 역할 선택 |
| 사용자 단위 | 예외 사용자의 메뉴가 그룹 설정과 충돌하지 않는가? | 사용자별 메뉴 등록과 중복 권한 |
| 실제 사용 | 메뉴 표시, 화면 진입, 조회·등록 동작이 기대와 같은가? | 메뉴 연결, 기능 권한, 대상 데이터 조건 |

특히 다음 사례를 별도로 확인한다.

- 조회 역할이 등록 또는 기준 정보 관리 화면으로 직접 들어갈 수 없는지
- 등록 역할이 자신에게 허용되지 않은 조직 또는 종료된 대상까지 수정할 수 없는지
- 일괄 적용 대상 중 일부만 메뉴가 보이는 경우, 누락 대상의 연결 관계와 역할 배정을 확인했는지
- 그룹 설정을 바꾼 뒤 개별 예외 사용자의 기존 권한이 예상치 않게 넓어지거나 줄지 않았는지

적용 결과와 확인 범위만 남기고, 운영 화면 주소·계정·조직 식별값은 기록하지 않는다.

## 완료 기록

작업 기록에는 요청 유형, 적용 대상 수의 범위, 적용한 메뉴의 기능 구분, 검증한 역할 범위, 예외 처리 여부와 누락·중복 여부를 남긴다. 실제 조직명, 사용자명, 접속 정보와 운영 메뉴 경로는 개인 원본에 보관한다.
