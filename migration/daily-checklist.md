# 일일 기록 이관 체크리스트

하루에 하나의 작은 주제 배치만 처리한다. 원본 파일은 OneDrive에 보존하고, 이 저장소에는 일반화한 Markdown만 작성한다.

## 시작 전

- [ ] `migration/backlog.md`에서 오늘 처리할 배치 하나를 선택한다.
- [ ] 원본의 파일명·형식·크기·하위 폴더만 먼저 확인한다.
- [ ] 계정, 비밀번호, 키, 서버·DB 접속 정보, IP, 고객·직원 개인정보, 메일·회의 원문, 고객 제공 파일 포함 여부를 확인한다.
- [ ] 민감한 원문만 있고 일반화할 학습·절차가 없다면 `제외`로 기록하고 다음 배치로 넘어간다.

## 작성

- [ ] 원본을 직접 복사하지 않고, 목적·처리 절차·검증 항목 중심으로 Markdown을 새로 작성한다.
- [ ] 파일명은 영문 kebab-case를 사용한다.
- [ ] 실제 회사·고객·사용자·운영 식별값은 일반 용어로 대체한다.
- [ ] SQL 예시는 실제 테이블명·데이터·운영 쿼리를 제거하고, 일반화된 예시만 쓴다.
- [ ] 새 문서에 작성일·분류·상태를 기록한다.

## 검토와 반영

- [ ] 민감정보 패턴(비밀번호·키·접속 문자열·IP·이메일·개인정보)을 검색한다.
- [ ] 링크와 상대 경로가 정상인지 확인한다.
- [ ] `migration/backlog.md`의 배치 상태와 완료 문서를 갱신한다.
- [ ] 변경사항을 하나의 명확한 커밋으로 만들고 GitHub에 푸시한다.

## 배치 크기 기준

- 텍스트 메모: 하루 2~5개 원본을 하나 또는 여러 개의 주제 노트로 통합
- 문서·PPT·이미지: 하루 1~2개만 읽고 일반화
- 코드·SQL·로그: 원문 반입 금지. 하루 1개 주제의 개념·체크리스트만 작성
